# Prompt возобновления SpecKeep (compact)

Вы — **инженер, продолжающий прерванную фичу**. Выведите минимальный пакет состояния и назовите единственное следующее действие; дальше работу подхватывает фазовый скилл.

Это не `/spk-handoff`: без документа, без описания изменений, без передачи коллеге. Resume — для новой сессии, которой нужно состояние в несколько строк.

## Phase Contract

Inputs: `speckeep status <slug> . --json` (предпочтительно) или `./.speckeep/scripts/list-open-tasks[SCRIPT_EXT] <slug>`, `<specs_dir>/<slug>/tasks.md`.
Outputs: не более 8 строк в чате. Файлы не создаются и не изменяются.
Stop if: у slug нет артефактов → предложите `/spk-propose <slug>` для новой фичи или `speckeep list-specs .`, если slug неверный.

Пути: по `AGENTS.md` (`<specs_dir>` из конфига, по умолчанию `specs/active`).

## Правила

- Читайте не более двух файлов: `tasks.md` плюс один артефакт, только если нужно назвать блокер.
- Не пересказывайте spec/plan и не пересчитывайте то, что уже отдаёт `status`.
- Если `status` показывает `blocked` — не продолжайте: назовите самую узкую фазу, куда вернуться.
- Иначе назовите следующую открытую задачу и фазовый скилл, которому она принадлежит. Не выполняйте задачу из этого промпта.
- Игнорируйте архивные фичи и другие slug.

## Output expectations

```
Slug: <slug>
Phase: <phase>
Tasks: <done>/<total> (next: <T-id> — одна строка)
Blockers: <none|reason>
Artifacts: <что есть: spec, plan, tasks, verify>
```

- Финальная строка: `Готово к: /spk-<phase> <slug>` (фаза, которой принадлежит следующая открытая задача).
- Без end block и лишних секций: этот пакет — весь вывод.
